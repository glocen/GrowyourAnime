# DevForum and creator-docs engineering tips

Research helper, 2026-11-24, for the builder. **Why it matters:** most of our players will be on phones. A phone runs out of memory or frame time long before a PC does, and an economy built on Voidkin can be wrecked by one exploit that copies them.
This keeps only the tips that hold in late 2026. Each tip is checked against `docs/engineering-plan.md` and the code on main.

**Labels:** SOURCED = Roblox's docs or a staff post. COMMUNITY = developers' reports, not checked by Roblox. OPINION = a judgement with no measurement behind it, mine or a forum poster's.
**Method:** WebSearch plus fetches. Normal devforum.roblox.com topic pages came back empty when fetched. The topic's `/t/<id>.json` address returned the first post, and that is how every staff post below was read. Other devforum threads are cited from search snippets only. create.roblox.com and about.roblox.com fetched fine.

## 1. Mobile performance and memory

1. **Test on one baseline phone from the start.** The docs' example targets are under 1,000 draw calls and under 1M triangles, figures from one game rather than a hard limit. Frame budget at 60 FPS: 16.67 ms. Studio's device emulator does not measure memory accurately. [Design for performance](https://create.roblox.com/docs/performance-optimization/design), [Memory](https://create.roblox.com/docs/projects/performance-optimization/memory). SOURCED.
   *For us:* name a baseline device (a phone with under 2 GB of memory, the dashboard's low-end line in tip 12) in `docs/test-requests.md`, and take the phone captures there.
2. **Streaming settings.** StreamingIntegrityMode `PauseOutsideLoadedArea`; StreamingMinRadius left at 64; TargetRadius left at 1024 but *tested at 64* to expose bugs; StreamOutBehavior `Opportunistic` to lower the risk of out-of-memory crashes. [Streaming techniques](https://create.roblox.com/docs/workspace/streaming/techniques). SOURCED.
   *For us:* these are Workspace properties saved in each place, not synced by Rojo, so check them in both the Main and Festival places. Add one self-test run at radius 64.
3. **Model streaming modes.** Use Atomic for groups that scripts need whole. Use Persistent sparingly: it never streams out, so it stays in memory. Never nest a persistent model inside an atomic one (the parent then acts persistent). Split large container models. Do distance checks and full-world queries on the server. [Techniques](https://create.roblox.com/docs/workspace/streaming/techniques). SOURCED.
   *For us:* **confirms** `FightService` (Atomic for Shades, PersistentPerPlayer only for a player's own lead). Check that a whole base kit isn't one giant model.
4. **SLIM level of detail.** Set `Model.LevelOfDetail = SLIM` on static models, each under about 64 cubic studs per the docs. `EnableSLIMAvatars` gives R15 players lightweight stand-ins; R6 rigs and NPCs are excluded. [Improve performance](https://create.roblox.com/docs/performance-optimization/improve). SOURCED.
   *For us:* worth trying on the Towers and the gate landmarks, judged from the player's camera. It does not help the fighters.
5. **Texture memory depends on pixel count, not file size.** Most minor images should be under 256x256 and most others need at most 512x512. A 1024 texture costs 4x a 512. Compressing before upload saves nothing. Tint one texture with `SurfaceAppearance.Color` instead of uploading colour variants. A duplicate upload loads twice. [Memory](https://create.roblox.com/docs/projects/performance-optimization/memory). SOURCED.
   *For us:* give the asset maker and the `tools/` texture scripts a size cap: 512 by default, 1024 only for a hero texture and only when named.
6. **Collision and render fidelity.** Box fidelity for small anchored parts (it has the lowest memory overhead), Box or Hull for medium ones. Set CanCollide, CanQuery and CanTouch all to false where none is needed: turning off collision alone still keeps the geometry in memory. Set `RenderFidelity` to Automatic or Performance. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED.
   *For us:* **confirms** `WorldService` and `RevealService`, which set all three to false. Gap: imported kit meshes (`src/storage/*Kit.rbxm`) probably keep the Default fidelity. Audit them once.
7. **Shadows and transparency.** Turn off `CastShadow` on small, distant and moving parts. Keep transparency at 0 or 1: layered partial transparency causes overdraw. [Improve](https://create.roblox.com/docs/performance-optimization/improve), [Design](https://create.roblox.com/docs/performance-optimization/design). SOURCED.
8. **Particle cost.** One emitter makes at most 400 particles per second, 100 on mobile. Cost grows with screen area covered (fill rate) and with overlapping layers. Flipbooks are the costliest texture, play at most 30 FPS, and *clients turn them off when low on memory*, which the docs say is likely on older phones. [Particle emitters](https://create.roblox.com/docs/building-and-visuals/lighting-and-effects/particle-emitters). SOURCED. Developers report that `Rate` drops with the player's graphics quality and that `:Emit(n)` gives the same burst everywhere. [thread](https://devforum.roblox.com/t/does-the-particleemitter-rate-have-a-significant-affect-on-performance/3006334). COMMUNITY.
   *For us:* use `Emit` for hit sparks. An effect's hero shape must survive with its flipbook layer gone, so review every effect once at the lowest quality level.
9. **Beams don't scale down.** They keep their segment count at every quality level. [Design](https://create.roblox.com/docs/performance-optimization/design). SOURCED. *For us:* keep beam segments low by default.
10. **Lighting.Technology is gone.** Unified Lighting has been fully live since 2025-07-23. Two properties replace Technology: `LightingStyle` (Realistic or Soft) and `PrioritizeLightingQuality`. Old settings mapped: Future became Realistic with the flag on, ShadowMap became Soft with it on, Voxel became Soft with it off. With the flag off, lighting quality drops first to protect performance. Neither property can be set from a script. [staff post](https://devforum.roblox.com/t/let-there-be-unified-light-unified-lighting-is-fully-live/3401512). SOURCED. The older "Future vs ShadowMap on phones" advice is **outdated**.
    *For us:* Lighting lives in each place. Pick both properties on purpose per place, and test the Festival at the flag's off setting on the baseline phone.
11. **MicroProfiler on a phone.** In the mobile Settings menu, turn MicroProfiler on, then open the IP and port it shows in a browser on a PC on the same network. Name your own code with `debug.profilebegin`/`profileend`. Orange frames mean worker jobs ran long; blue frames mean rendering did. Mobile is the best place to profile. [MicroProfiler](https://create.roblox.com/docs/performance-optimization/microprofiler). SOURCED.
    *For us:* add labels around FightService's step and the `NL_Effects` and `NL_FightShake` render steps, so a capture names our cost.
12. **Performance dashboard.** It shows a crash insight for Android phones under 2 GB, plus server CPU and memory by category, with p90 views. [staff post, 2024-09-03](https://devforum.roblox.com/t/analytics-optimize-low-end-android-crash-rates-server-memory-and-cpu-performance/3145364). SOURCED. *For us:* read it after the first public build, then weekly.
13. **Leaks.** Disconnect connections on Player objects yourself, enable `Workspace.PlayerCharacterDestroyBehavior`, clear per-player tables at leave, and watch LuaHeap and InstanceCount. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED.
    *For us:* `Net` clears its buckets on PlayerRemoving (**confirms**). Check the Workspace property in both places.
14. **Keep ReplicatedStorage and ReplicatedFirst lean.** The client loads everything in them. Preload only what the spawn area needs. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED. *For us:* **confirms** the templates sitting in ServerStorage.

## 2. Combat feel and many fighters

15. **Server Authority** (newsroom 2026-07-09; its linked devforum post is titled "Full Release") is prediction plus rollback for actions *the player times*. [newsroom](https://about.roblox.com/newsroom/2026/07/creating-responsive-cheat-resistant-games-roblox-server-authority), [docs](https://create.roblox.com/docs/projects/server-authority). SOURCED. *For us:* **confirms** "Server Authority: off". The reopen trigger stays as written.
16. **Pin server-run NPCs to the server.** `SetNetworkOwner(nil)` on the root stops the stutter when physics ownership passes between client and server. [thread](https://devforum.roblox.com/t/humanoid-moveto-jitters-with-client-network-ownership/3946259). COMMUNITY. *For us:* **confirms** FightService.
17. **Cheaper NPCs.** Turn off Humanoid states a fighter never uses, play NPC animations on the client, pool models instead of destroying them, and spawn only near players. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED. Whether turning off states helps is disputed and unmeasured. [thread](https://devforum.roblox.com/t/how-to-optimize-humanoids/389801). COMMUNITY.
    *For us:* **confirms** client-played clips (`FighterController`). Next: turn off Climbing, Swimming and Seated on fighters, keep it only if the MicroProfiler shows a gain, and pool Shades between stretches.
18. **When the enemy count grows.** Past roughly 50 to 100 NPCs, developers split simulation from rendering. The server sends compressed positions 10 to 20 times a second and the client interpolates. Astro Force, 100 units: 60 Hz cut to 10 Hz, positions packed into Int16 (35 KB/s down to 10 KB/s), only changed units sent, 60x less in all. [Astro Force, 2021](https://devforum.roblox.com/t/how-we-reduced-bandwidth-usage-by-60x-in-astro-force-roblox-rts/1202300), [NPC threads](https://devforum.roblox.com/t/optimizing-hundreds-of-moving-npcs-rendering/3074292). COMMUNITY (old post, the technique still holds).
    *For us:* not needed at today's counts. It is the plan to reach for if the Calamity or Festival packs grow, and only after reading the Developer Console's receive rate.
19. **Hit detection.** For combat, Touched is called unreliable; spatial queries suit area hits; raycasts suit blades. [thread](https://devforum.roblox.com/t/melee-hitboxes-what-is-the-best-solution-and-is-the-touched-event-really-that-bad/867477). COMMUNITY. *For us:* **confirms** pure-math reach (`Fight.Reaches`). Keep Touched out of combat.
20. **Hitstop.** `track:AdjustSpeed(0)` on the attacker's and the victim's tracks, then restore. Reported pitfalls: a track can drift a frame after the freeze, and a long freeze can stop replicating. [thread](https://devforum.roblox.com/t/animation-still-sometimes-continue-after-freezing-it/2927980). COMMUNITY. *For us:* **confirms** holds played locally in `Effects`. Never freeze from the server.
21. **Camera shake.** Use noise (Perlin), scale it by trauma squared, let it decay, and bind it after the Camera render priority. [thread](https://devforum.roblox.com/t/how-to-make-smooth-adjustable-screen-shake-using-mathnoise/2177926). COMMUNITY. Rules 2 and 3 rule out the published modules. *For us:* **confirms** our own `NL_FightShake`. I found no Roblox source on a reduce-shake option; adding a setting is OPINION.
22. **Animation Graphs, fully released 2026-07-15.** Blend1D and Blend2D with phase sync, masks for upper-body layers, and Over, Add and Subtract nodes. Parameters are set with `track:SetParameter`, graphs replicate on their own, and `LoadAnimation` code keeps working. [staff post](https://devforum.roblox.com/t/full-release-animation-graphs-create-complex-character-motion-visually/4739840). SOURCED.
    *For us:* a tier 1 experiment for walk-to-run by speed (today the walk's speed is set with AdjustSpeed) and for upper-body attack masks. Not a rewrite. Graph assets must be group-owned.

## 3. Networking and security

23. **Validate every argument a client sends.** Check that an Instance is really one (`typeof(x) == "Instance"`) and sits where expected (`IsDescendantOf` a known folder). Use `math.isfinite`, because NaN passes type checks and fails every comparison. Check every key of a client table and cap their number. Limit string length and check UTF-8 with `utf8.len`. Check that values are above zero and that ids are real. [Client-server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary). SOURCED.
    *For us:* `Rules.Base` already refuses NaN (**confirms**). Gap: one shared argument checker that every `Act` action declares its arguments through, so no handler can skip it.
24. **Rate limits on the server only.** Use a token bucket and clear it at leave. Limit anything that ends in `FireAllClients`: the server is "a gatekeeper, not just a relay". Never trust the client for `PromptProductPurchaseFinished`, ProximityPrompt properties, ClickDetector, an instance path to change, or an unanchored part it can own. [same page](https://create.roblox.com/docs/scripting/security/client-server-boundary). SOURCED. *For us:* **confirms** `Net.luau`.
25. **Rollback exploits.** Blocking a save lets a player redo a rare outcome. A NaN or invalid UTF-8 written into a saved field makes the save fail, which forces the same rollback. [thread, 2022](https://devforum.roblox.com/t/exploiting-how-to-prevent-exploiters-from-abusing-data-store-rollbacks-and-sanitizing-against-data-store-vulnerabilities/2019989). COMMUNITY.
    *For us:* add a logic case that writes `"\255"` and `0/0` into `Nickname` and every settings field. Weigh one `profile:Save()` after a Mythical reveal (it costs one UpdateAsync).
26. **UnreliableRemoteEvent.** The payload limit has been 1000 bytes since 2025-03-12 (it was 900). Delivery is unordered and can be dropped, and it gets no priority over other traffic. It is for cosmetic events only. [staff post](https://devforum.roblox.com/t/introducing-unreliableremoteevents/2724155). SOURCED. *For us:* **confirms** `View` as unreliable and `Hit` as reliable.
27. **Bandwidth.** There's no official per-player budget now. Developers cite about 50 KB/s, and say a total over 100 KB/s needs work. Measure in the Developer Console. [thread](https://devforum.roblox.com/t/what-should-the-total-data-kbs-be-for-a-project/3737312). COMMUNITY. The docs say to send only what changed, never the whole inventory. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED.
    *For us:* **gap**. `DataService` fires the whole read copy (`Profile`) after every change, and that copy grows with every item and Voidkin. Send only the sections that changed.
28. **Parallel Luau and native code.** Parallel Luau fits heavy, isolated work only: use few actors, and switching threads has its own cost. [Parallel Luau](https://create.roblox.com/docs/scripting/multithreading). SOURCED, plus COMMUNITY on the overhead. Native code generation is suggested for server scripts. [Improve](https://create.roblox.com/docs/performance-optimization/improve). SOURCED.
    *For us:* neither is needed now. If a MicroProfiler label shows `Rules.Hit` as hot, try `@native` on it first.

## 4. Data and analytics

29. **Data store limits since 2026-07-29.** Storage is 500 MB + 1 MB x lifetime players, and in-game and Open Cloud requests share one budget (base 300). Per key: 4 MB/min written, 25 MB/min read, values up to 4 MB. Ordered writes: 30 + 5 x players per minute. [Limits](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits), [staff post](https://devforum.roblox.com/t/unifying-data-stores-open-cloud-and-game-apis-and-increasing-storage-limits/4739240). SOURCED.
    *For us:* plenty. `TowerBoardService` opens a new ordered store each week, and each one stays in storage for good. Small, but worth knowing.
30. **ProfileStore.** If `StartSessionAsync` returns nil, kick the player. `Steal` is for debugging only. `Save()` costs one UpdateAsync, so call it only at critical moments. Put final writes in `OnLastSave`, not `OnSessionEnd`. `Mock` exists for Studio. [API](https://madstudioroblox.github.io/ProfileStore/api). SOURCED.
    *For us:* **confirms** the save layer. Check that no final write hangs off `OnSessionEnd` (DataService:184).
31. **Receipts after 2026-09-22.** Listed products can now be bought outside the game. Such a purchase can arrive *before the player's data loads*. Claim each `PurchaseId` atomically. Use `BindReceiptHandler` so each system handles only its own product ids. Random or limited items stay Unlisted. The "needs a fix" banner hides broken products outside the game. [staff post](https://devforum.roblox.com/t/fix-the-processreceipt-needs-a-fix-banner-and-sell-your-products-outside-your-game/4910527). SOURCED.
    *For us:* when `ProductManager` is adapted: one handler per product, wait for the profile, and write the purchase id inside the same `Transaction`. Rule 4: nothing random is ever Listed.
32. **MemoryStore.** Quota 64 KB + 1.2 KB x users. Requests: 1000 + 120 x CCU units per minute. Items up to 32 KB, kept at most 45 days. For short-lived data only. [Memory stores](https://create.roblox.com/docs/cloud-services/memory-stores). SOURCED. *For us:* fine for a cross-server board cache. Never the only home of a reward.
33. **MessagingService.** Sends: 600 + 240 x players per minute per server. Messages up to 1 KB. Subscriptions: 20 + 8 x players. Delivery is best effort. [staff post via snippet](https://devforum.roblox.com/t/enhanced-messagingservice-limits/2835576). SOURCED (search snippet). *For us:* ProfileStore already uses it, so keep our own use small.
34. **AnalyticsService.** Requests: 120 + 20 x CCU per minute. Caps: 10 economy resource types, 10 funnels of 100 steps, 100 custom event names, 3 custom fields per event. Log an economy event only *after* the change succeeds. Use one currency with a custom field for variants. Data is kept 90 days, and charts take about 24 hours to appear. [Event types](https://create.roblox.com/docs/production/analytics/event-types). SOURCED.
    *For us:* **gap**. `FunnelService` logs only the onboarding funnel. Log economy source and sink events from the one Transaction commit, and add a recurring funnel for break, reveal and assign.

## 5. Changes in 2025 and 2026

35. **The new Luau type solver** is generally released (2025-11-20). Places with strict scripts stay on the old solver until `UseNewLuauTypeSolver` is set to Enabled. It runs at edit time only. [staff post](https://devforum.roblox.com/t/general-release-luau%E2%80%99s-new-type-solver/4084991). SOURCED.
    *For us:* `luau_check.py` already runs the new solver. Enable the property in both places so Studio's Script Analysis and our check agree.
36. **The Input Action System** is fully released (2026-06-11). The default player scripts are moving onto it: the default becomes Enabled around early 2027 and the old scripts are removed around mid 2027. [staff post](https://devforum.roblox.com/t/full-release-input-action-system-ias-newly-converted-player-scripts/4678416). SOURCED.
    *For us:* `BaseView` drives the ControlModule and `SlamController` uses ContextActionService. Playtest with `Workspace.PlayerScriptsUseInputActionSystem` Enabled before early 2027.
37. **SignalBehavior.** New templates default to Deferred. Older places' "Default" is still documented as Immediate, with no date for the switch. [Deferred events](https://create.roblox.com/docs/scripting/events/deferred). SOURCED. *For us:* check what our places use. Code shouldn't depend on handlers running immediately.
38. **EditableImage and EditableMesh** draw on a per-device memory budget, and creating one can return nil. [beta thread](https://devforum.roblox.com/t/client-beta-in-experience-mesh-image-apis-now-available-in-published-experiences/3267293). COMMUNITY plus staff replies. *For us:* unused today. If we ever use them, handle the nil.
39. **The new audio API** (AudioPlayer, AudioEmitter and so on): I found no official benchmark, and one staff reply calls it comparable to a Sound. [thread](https://devforum.roblox.com/t/new-audio-api-beta-elevate-sound-and-voice-in-your-experiences/2848873). COMMUNITY. *For us:* move only if we need an effects chain.

## Gaps in our plan

- **A phone budget.** No baseline device, no draw-call or texture-size cap, no low-quality-level effect pass, no MicroProfiler labels (tips 1, 5, 8, 11). The plan's "How each system is tested" table has no performance row.
- **Place settings outside Rojo.** Streaming radius and integrity, StreamOutBehavior, `PlayerCharacterDestroyBehavior`, SignalBehavior, Unified Lighting's two properties, `UseNewLuauTypeSolver`, and the Input Action System player-scripts flag (tips 2, 10, 13, 35 to 37). Nothing records what each place holds. A short per-place checklist in the plan's "Places" section would.
- **The whole profile sent on every change** (tip 27).
- **No economy analytics** (tip 34).
- **Receipts:** the outside-the-game sales rules (tip 31) belong in the store's design before `ProductManager` is adapted.
- **Save-poisoning cases** with NaN and invalid UTF-8 in saved strings (tip 25).

## Top 5 to act on

1. **Write a per-place settings checklist** into the plan's "Places" section and apply it in both places: streaming radius tested at 64, `Opportunistic`, `PauseOutsideLoadedArea`, `PlayerCharacterDestroyBehavior`, LightingStyle and the lighting flag, `UseNewLuauTypeSolver` (tips 2, 10, 13, 35).
2. **Add a performance row to the test table:** a named baseline phone, the MicroProfiler with our own labels, every effect reviewed at the lowest quality level, a 512 texture cap (tips 1, 5, 8, 11).
3. **Send profile changes by section, not the whole read copy,** before item and Voidkin counts grow (tip 27).
4. **Log economy events from the Transaction commit** and add a recurring core-loop funnel (tip 34).
5. **Harden the save against poisoning:** one shared argument checker for `Act`, plus logic cases with `"\255"` and `0/0` in every saved string and number (tips 23, 25). When the store is built, apply tip 31.
